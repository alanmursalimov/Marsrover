# Software and Raspberry Pi setup

## Pi (kskpi1)
- School Raspberry Pi, hostname `kskpi1`. Teacher said Alan can do almost anything with it.
- Goal: wireless dev "server" – only a power cable, joins known Wi-Fi networks automatically.
  Wi-Fi: school network `campus-wlan`.
- Up to 3 people work on the code.
- Always-running service (set up 2026-11-05, starts on power-up, systemd name `marsrover`):
  pulls this repo every 5 seconds and runs the code when it changes. It stops running
  programs with SIGTERM and has no keyboard.
- They also code on the Pi using Thonny.

## Workflow (decided)

## Code structure
- Teacher's guidance: use a library for the rover code that `main.py` calls. Alan writes `main.py`
  himself; he doesn't need to understand the library code.
- `rover.py` – library for the Grove I2C Motor Driver v1.3 (German user guide in the docstring at the top).
  - `Rover(addresses=None, max_speed=60, invert_left=False, invert_right=False, swap_sides=False, grovepi_address=0x04, left=None, right=None)`
    (`addresses=None` → `[0x0F]`, or the addresses used in `left`/`right`; `addresses=[]` = no motor driver, for testing sensors/servos only).
  - Added 2026-11-10 (tested only with a fake bus): `left=[(0x0F, "J1"), ...]`, `right=[...]` set which motor
    (driver address, terminal J1/J5) belongs to which side; without them the J1-left/J5-right convention applies.
    `rover.motor(address, "J1"/"J5", invert=False)` → `.speed(-100..100, seconds=None)`, `.stop()` drives one motor
    and leaves the others as they are.
  - `motortest.py` (added 2026-11-10): talks to the motor driver directly over smbus (no `rover.py`), runs
    J1/J5 forward/backward for 2 s each. Args: `address terminal percent pwm_hz`, e.g. `motortest.py 0x0F J5 70`.
    Percent is of battery voltage (no `max_speed` limit). Optional PWM frequency register 0x84.
  - Ports chosen by the user in main.py (added 2026-11-07, tested only with a fake bus, not on the Pi yet):
    `rover.analog("A0"–"A2")`, `rover.digital_in/digital_out/ultrasonic("D2"–"D8")`,
    `rover.servo(channel=0–15, address=0x7F, min_us=1000, max_us=2000, max_angle=180)` → `.angle(deg)`, `.off()`.
    Each port can only be used once (error otherwise). GrovePi parts need the Dexter `grovepi` library on the Pi
    (imported only when a sensor is used). Servo code talks to the PCA9685 directly over smbus and turns off
    its ALLCALL address (0x70, same as the TCA9548A hub's default).
    0x7F is Seeed's documented default for the PWM board – not checked with i2cdetect yet.
  - Speed 0–100 = % of `max_speed` (not full battery voltage).
  - `drive(left, right, seconds=None)`, `forward`, `backward`, `turn_left`, `turn_right` (tank turn on the spot),
    `stop()`, `wait(s)`, `wasd(speed=50)` (W/A/S/D, space = stop, Q = quit).
  - Without `seconds`, motors keep running until the next command or until main.py ends (then they stop).
  - Wiring convention per driver: terminal **J1** (IN1/IN2 LEDs) = LEFT motor, **J5** (IN3/IN4) = RIGHT motor.
  - Safety: motors stop automatically on exit, crash, Ctrl+C or SIGTERM. Test with wheels in the air.
  - `wasd()` only works when main.py is started manually in a terminal:
    `sudo systemctl stop marsrover` then `python3 ~/Marsrover/main.py`.
  - Troubleshooting: "Motortreiber … antwortet nicht" → check Grove cable, run `i2cdetect -y 1`.
    Very slow scan → a driver blocks the bus (like board no. 3) – unplug it.
    `i2cdetect -y 1` skips 0x00–0x07 and 0x78–0x7F (GrovePi 0x04, PWM 0x7F) → use `i2cdetect -y -a 1`.
  - `forward(50, 50)` means speed 50 for **50 seconds** (2nd argument is `seconds`) – use `seconds=` by name.
- User guide (German, PDF): `docs/Marsrover_Anleitung.pdf`, generated by `docs/make_anleitung.py`
  (ReportLab). Regenerate it whenever the library's commands change (last update 2026-11-10).
- `main.py` – Alan's test file (as of 2026-11-10: `rover.forward(50, 50)` plus an ultrasonic read loop on D2).
